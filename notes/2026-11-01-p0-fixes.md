## P0-C：重连之后事件订阅再也不发 → "喊不应"（插件侧，本文件）

### 证据（不是猜的）

`…\versions\1.21.1-NeoForge_21.1.265\logs\sirius_bridge.log`（bridge 自己的审计日志）：

```
端口 61692  339 次   21:00:10 → 21:50:50   ← 重启 MC 前的旧连接，每次连接第一件事都是 events.subscribe
端口 49229    9 次   21:51:08 → 21:51:21   ← 关服前最后一条
端口 49994 2269 次   21:52:43 → 22:44:44   ← 新 jar 之后**唯一**一条，2269 个请求里 **0 个** events.subscribe
```

而真机测试里 `sirius_status.diagnostics.watchdog` 一直冻在
`received: 3 / matched: 0 / delivered: 0 / lastEventMsAgo ≈ 40 分钟` ——
`received` 数的是**所有**通知（不只聊天），期间开过箱子/交易/铁砧/死亡屏，一条 `gui_open` 都没到。
同一时间 `sirius_chat_history`（拉取式 RPC，读客户端聊天环）一直正常，所以测试报告里 D1/D2 是过的、H5 挂。

### 根因

`BridgeLink` 里 `#subscribed` 这个集合**跨连接存活**：连接关闭时只清 socket/pending，
`subscribe()` 的第一句是 `if (wanted.size === this.#subscribed.size) return`
→ 插件重连后重置了自己的旗标、老老实实调 `link.subscribe(...)`，结果被这一句早退挡掉，
新连接上从来没发过 `events.subscribe`。只要 MC/bridge 重启过一次就会中招。

### 修法

把"我想订阅什么"和"这条连接订到了什么"分开：

| 字段 | 语义 | 生命周期 |
|---|---|---|
| `#wanted` | 插件想要的事件种类 | 跨连接累积（插件只说一次"我要 chat/death/…"） |
| `#subscribed` | **这条连接**已订阅成功的种类 | 连接级：`close` / `#teardown` / `hello_ack` 都清零 |

`hello_ack` 成功时：清零这两类连接级状态（含 `#events`，因为 seq 是**按连接**从 0 重排的，
留着旧的高 seq 会让 `events({since})` 全过滤空）→ 然后 `#resubscribe()` 自动把 `#wanted` 发过去。
失败只记日志，下一次工具调用还会再试。

顺带把"订阅丢了"变成可见的：`sirius_status` 在 `online` 但 `diagnostics.subscribedTypes` 为空时，
摘要里直接打一行 `⚠ 事件订阅为空：听不到聊天/喊你（重连一下或重启 DSH）`。
（以前只能从 `watchdog.received` 冻住推断，数字本身看不出异常。）

### 文件改动

| 文件 | 改动 | 为什么 |
|---|---|---|
| `src/bridge.mjs` | 新增 `#wanted`；`subscribe()` 改成"想要集合 vs 连接级已订集合"；`hello_ack` 后 `#resetConnectionState()` + `#resubscribe()`；`close`/`#teardown` 也重置；新增 `get subscribed()` | 订阅是连接级的，不重置就永远发不出去 |
| `src/plugin.mjs` | `diagnostics.subscribedTypes = link.subscribed` | 让"喊不应"在 `sirius_status` 里一眼可见 |
| `src/tools.mjs` | `sirius_status` 摘要加"⚠ 事件订阅为空"；`sirius_use_item` 结果词表补 `incomplete` + 证据字段说明（按住/饱食） | 前者是事故判据，后者跟桥侧 1.6.2 的语义对齐 |
| `src/prompt.mjs` | 提示词补一句"吃/喝由桥按住到进度条走完，`used` 是真吃了，`incomplete` 是没吃成（别重试）" | 免得模型拿旧语义重试 |
| `test/bridge.test.mjs` | 新增 2 条：① 断线重连后必须再发一次 `events.subscribe` 且事件缓冲/订阅清零 ② "想要集合"跨连接保留，重连一次发齐 | 回归锚点，防止这个 bug 回来 |
